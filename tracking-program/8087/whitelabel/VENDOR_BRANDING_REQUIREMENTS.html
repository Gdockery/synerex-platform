Whitelabel Branding Requirements for Vendors

Overview

This document outlines the branding assets (logos, graphics, and images) required to customize the portal for your organization. The portal supports URL-based whitelabeling, meaning different domains can display different branding while using the same codebase.

Directory Structure

When providing your branding assets, please organize them in the following directory structure:

whitelabel/ └── {your-domain}/ ├── images/ │ ├── logo-small.png │ ├── logo-big.png │ ├── logo-big1.png │ ├── xeco-logo-sm.png │ ├── xeco-welcome2.png │ ├── ubill-tracker-logo.png │ ├── ubill-cast-logo.png │ └── (other images as needed) └── pdf-resources/ ├── logo.png ├── bill-cover.png ├── bill-logo.png ├── proposal-cover.png └── (other PDF resources as needed)
Note: Replace {your-domain} with your subdomain identifier. For example:
  • harmoniq.synerexlabs.com → use directory harmoniq/
  • ucep.synerexlabs.com → use directory ucep/

File Naming Requirements

  • Exact filenames: Use the exact filenames listed above (case-sensitive)
  • File extensions: Use .png for images with transparency, .jpg or .png for photos
  • No spaces: Use hyphens (-) instead of spaces in filenames
  • Lowercase: Use lowercase letters for consistency

Image Specifications

General Guidelines

  1. Format: PNG for logos and graphics with transparency, JPG for photos
  2. Resolution:
    • Web images: 72-150 DPI is sufficient
    • PDF resources: 300 DPI recommended for print quality
  3. Color Space: RGB (not CMYK)
  4. Transparency: Use PNG with alpha channel for logos that need transparent backgrounds
  5. File Size: Optimize images for web (compress without visible quality loss)

Logo Requirements

  • Transparent Background: All logos should have transparent backgrounds (PNG with alpha channel)
  • High Contrast: Ensure logos are readable on both light and dark backgrounds
  • Scalable: Logos should look good when scaled down to small sizes
  • Brand Colors: Maintain brand color accuracy

Delivery Instructions

  1. Organize files in the directory structure shown above
  2. Name files exactly as specified (case-sensitive)
  3. Provide all required assets - missing files will fall back to default branding
  4. Include a README with any special instructions or notes about your branding
  5. Test files - ensure all images open correctly and have proper dimensions

Optional Customizations

Additional Images

If you have additional images you'd like to use (e.g., custom icons, graphics), you can include them in your images/ directory. However, these will only be used if the application code is updated to reference them.

Client-Specific Logos

Client company logos are managed separately through the application interface and are stored in /images/client_company_logo/. These do not need to be included in your whitelabel package.

Testing Your Branding

After your branding assets are installed:

  1. Access your portal at {your-domain}.synerexlabs.com
  2. Verify logos appear correctly in:
    • Navigation bar (top left)
    • Login page
    • Welcome/dashboard page
    • Generated PDF documents
  3. Check that images load properly and maintain aspect ratios
  4. Verify PDF documents display your branding correctly

Support

If you have questions about:

  • File formats or specifications: Contact your project manager
  • Technical implementation: Contact the development team
  • Branding guidelines: Refer to your organization's brand guidelines

Important Notes

Portal Domain: If your domain is portal.synerexlabs.com, it will always use default branding (no whitelabel directory needed)
Partial Branding: You can provide only some assets - missing files will use defaults
Updates: Branding assets can be updated at any time by replacing files in the whitelabel directory
Version Control: Whitelabel directories are not tracked in git, so your branding remains private to your deployment
